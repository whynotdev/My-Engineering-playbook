# My Engineering Playbook

A practical, GitHub-friendly engineering reference for making software design decisions.

**Primary stack:** Java · Spring Boot · React · PostgreSQL · Git/GitHub  
**Secondary areas:** System design · Cloud · DevOps · CI/CD · Generative AI · Agentic AI

## How to use this repository

1. Start with [Decision Frameworks](01-decision-frameworks/README.md).
2. Use the decision records when a choice has meaningful long-term consequences.
3. Copy the checklists into real projects and adapt them to project constraints.
4. Add lessons from production incidents, delivery estimates, and cost reviews.
5. Revisit provider-specific prices and product capabilities before making a current purchasing decision.

## Core principle

Choose the simplest solution that meets the requirements, can be operated safely, and has a clear path to evolve. Do not add technologies just because they are popular.

## Suggested learning order

1. Technology selection
2. Architecture selection
3. Database selection
4. Hosting and cloud selection
5. Authentication and API design
6. Cost, scaling, and production readiness
7. Project blueprints and deeper technology notes

## Status

This is a living reference. Treat examples as starting points, not universal prescriptions. Validate security, compliance, costs, and provider features for each real project.
