# Maintaining This Playbook

## Writing style

- Prefer practical rules and examples over long theory-only explanations.
- State assumptions and explain trade-offs.
- Separate stable engineering principles from provider-specific details that may change.
- Include security, operations, maintenance, and cost implications where relevant.
- Avoid claiming a technology is always best.

## Suggested page template

1. Problem / overview
2. Requirements and constraints
3. When to use
4. When not to use
5. Alternatives and trade-offs
6. Security and operational concerns
7. Cost and scaling considerations
8. Example architecture
9. Decision checklist
10. Sources / last verified date, when current facts are involved

## Change process

For consequential choices, add an Architecture Decision Record (ADR) using `01-decision-frameworks/10-architecture-decision-record-template.md`.
